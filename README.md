# Coffee Shop API

Учебный REST API-проект кофейни, разработанный на Java и Spring Boot. Проект предназначен для практики backend-разработки и автоматизированного тестирования API.

## О проекте

Coffee Shop API — backend-приложение, реализующее базовые операции с пользователями и их заказами.

На текущем этапе реализованы две основные сущности:

- **User** — пользователь с уникальным email и именем.
- **Order** — заказ, связанный с пользователем. Содержит описание, статус и дату создания.

Проект построен с разделением ответственности между Controller, Service и Repository. Для взаимодействия с базой данных используется Spring Data JPA, а для управления схемой БД — Flyway.

Отдельное внимание уделено тестированию: проект включает unit-тесты, тесты репозиториев и API-автотесты.

## Запуск проекта

### 1. Требования

Перед запуском убедитесь, что установлены:

- Java 21;
- Maven;
- Docker Desktop или Docker Engine;
- Git.

### 2. Клонирование репозитория

```bash
git clone https://github.com/Nikitajc1/CoffeeShopApi.git
cd CoffeeShopApi
```

### 3. Настройка переменных окружения

В корне проекта создайте файл `.env`:

```env
POSTGRES_DB=coffee_shop
POSTGRES_USER=coffee_user
POSTGRES_PASSWORD=your_password
```

Укажите собственный пароль для PostgreSQL.

Файл `.env` не должен попадать в Git. Для публикации проекта рекомендуется использовать `.env.example` с демонстрационными значениями без реальных секретов.

### 4. Запуск PostgreSQL

Выполните команду:

```bash
docker compose up -d
```

Проверить состояние контейнера можно командой:

```bash
docker compose ps
```

PostgreSQL будет доступен по адресу:

```text
localhost:5432
```

База данных и пользователь создаются автоматически при первом запуске контейнера.

### 5. Запуск Spring Boot

При запуске приложения через Maven необходимо передать переменные окружения из `.env`.

Для macOS и Linux:

```bash
set -a
source .env
set +a
```

После этого запустите приложение:

```bash
mvn spring-boot:run
```

Spring Boot подключится к PostgreSQL. Flyway автоматически применит миграции при запуске приложения.

REST API будет доступен по адресу:

```text
http://localhost:8080
```

## API Endpoints

Базовый адрес:

```text
http://localhost:8080/api
```

### Users

| Метод | Endpoint | Описание |
|---|---|---|
| POST | `/users` | Создание пользователя |
| GET | `/users/{id}` | Получение пользователя по ID |

Пример создания пользователя:

```json
{
  "name": "Alex",
  "email": "alex@example.com"
}
```

### Orders

| Метод | Endpoint | Описание |
|---|---|---|
| POST | `/orders` | Создание заказа |
| GET | `/orders/{id}` | Получение заказа по ID |
| GET | `/orders/user/{userId}` | Получение заказов пользователя |
| GET | `/orders/user/{userId}/{status}` | Получение заказов пользователя по статусу |

Пример создания заказа:

```json
{
  "userId": 1,
  "description": "Cappuccino",
  "status": "NEW"
}
```

Допустимые статусы заказа:

- `NEW`
- `IN_PROGRESS`
- `COMPLETED`

## Обработка ошибок

В приложении реализована централизованная обработка исключений через `@RestControllerAdvice`.

Основные HTTP-статусы:

| Статус | Описание |
|---|---|
| 200 OK | Успешное получение данных |
| 201 Created | Успешное создание ресурса |
| 400 Bad Request | Ошибка валидации входных данных |
| 404 Not Found | Пользователь или заказ не найден |
| 409 Conflict | Пользователь с таким email уже существует |

Ошибки возвращаются в едином формате `ErrorResponse`.

## Тестирование

Проект содержит три направления тестирования:

**1. Unit-тесты**

- JUnit 5;
- Mockito;
- проверка бизнес-логики сервисного слоя;
- проверка успешных и негативных сценариев.

**2. Repository-тесты**

- Spring Boot Data JPA Test;
- PostgreSQL;
- проверка сохранения и получения данных;
- проверка связей между сущностями;
- проверка ограничений базы данных;
- проверка derived queries.

**3. API-автотесты**

- REST Assured;
- JUnit 5;
- Hamcrest;
- DataFaker;
- JDBC.

API-тесты проверяют HTTP-статусы, структуру и содержимое JSON-ответов, позитивные и негативные сценарии, а также взаимодействие приложения с PostgreSQL.

Для очистки тестовых данных используется отдельный `TestDataCleaner`, работающий через JDBC.

### Запуск тестов

API-автотесты обращаются к работающему приложению по адресу `localhost:8080`. Поэтому перед запуском полного набора тестов необходимо:

1. Запустить PostgreSQL через Docker Compose.
2. Запустить Spring Boot.
3. В отдельном терминале передать переменные окружения из `.env`.
4. Выполнить:

```bash
set -a
source .env
set +a

mvn test
```

Команда запускает весь набор Maven-тестов.

## База данных

Схема базы данных управляется с помощью Flyway.

На текущем этапе используются две таблицы:

- `users`;
- `orders`.

Основные ограничения:

- email пользователя уникален;
- заказ обязательно связан с существующим пользователем;
- удаление пользователя с существующими заказами запрещено ограничением внешнего ключа;
- статус заказа ограничен допустимыми значениями.

Hibernate работает в режиме `ddl-auto=validate`: проверяет соответствие Entity существующей схеме, но не изменяет её самостоятельно.
